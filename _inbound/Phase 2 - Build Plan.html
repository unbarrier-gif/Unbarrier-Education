01 · Scope

What's in, what's out

In scope

Phase 2 ships

  • Production homepage at unbarrier.me
  • Production landing at loop.unbarrier.me
  • Guest Host Kit template engine (data → page)
  • Live /loop/host/nicki-hambleton
  • Template-ready /loop/host/gemma (toggle to live)
  • Blog system + index + post template at /blog
  • MDX content pipeline (frontmatter, reading time, OG)
  • Footer + nav wired across all four route trees

Out of scope — Phase 3

Not this phase

  • Newsletter component + /subscribe page
  • Stripe payment links wired in product
  • TidyCal embeds (still link-out only)
  • /hello contact page
  • High-contrast toggle
  • RSS feed + Atom
  • Accessibility statement v2 + feedback form
  • Search on the blog

Why this split

Phase 2 is "can a stranger find you, trust you, and book a room". Phase 3 is "can they subscribe, pay, and come back". Don't blend them — Phase 2's success is measured in routes that work and pages that read right, not in conversion infra.

  2. Design tokens package (@unbarrier/design-system) consumed by both apps. Tokens match colors_and_type.css in this project.

  4. Global a11y CSS — skip link, focus rings, prefers-reduced-motion handler, contrast fix.
  5. SEO scaffolding — sitemap, robots, Organization + Person JSON-LD on root layouts.
  6. Footer with company line ("Unbarrier Education Ltd · Company No. 16603630") on every page.
  7. DNS — loop.unbarrier.me live, vision.unbarrier.me → loop.unbarrier.me 301.
  8. CI — Lighthouse + axe in PR checks; both pass on the placeholder routes.

If anything above is missing

Open it as a Phase 1 hotfix PR before starting Phase 2 work. Don't paper over it from inside a Phase 2 PR — keeps the diff readable.

05 · Guest Host Kit

The template engine Build

The kit is two surfaces: a generic kit at /host (what hosting Loop Breakers looks like — the same for everyone), and a per-host page at /host/[slug] (a personal intro letter + the kit, tailored). Today these exist as standalone HTML files. Phase 2 turns them into a content-driven engine so adding a new host is a data change, not a code change.

Source mocks (canonical)

  • loop-breakers/guest-host-kit/index.html — the shared kit
  • loop-breakers/guest-host-kit/Nicki Hambleton - Personal Intro.html — Nicki's personal letter
  • loop-breakers/guest-host-kit/Gemma - Personal Intro.html — Gemma's personal letter

Architecture

Content directory
apps/loop/content/hosts/[slug].mdx
Frontmatter shape
name, role, tagline, sessionTheme, sessionDate, portrait, accent, status ('live' | 'draft')
Body
The personal-intro letter — MDX so Nici can drop in callouts, the testimonial echo, links
Page
app/host/[slug]/page.tsx — reads MDX, composes <PersonalIntro> + <HostKit> + <CTA>
Shared kit
app/host/page.tsx — renders <HostKit> standalone (no personal intro)
Toggle to live
Set frontmatter status: live → page indexed and linked from /host's "current hosts" strip. status: draft → noindex, accessible only by direct URL.

Components

ComponentPurposeNotes
<PersonalIntro>The "Hey [name], here's why I'm asking you" letterMDX body. Optional <TestimonialEcho> child for verbatim quote-back.
<HostKit>The shared kit — what hosting looks like, what they get, what we askStatic. Reads from one MDX source so edits are central.
<HostCTA>Two-route CTA — book a prep call OR reply by emailPrep call link is the host's TidyCal page (per-host frontmatter field).
<HostStrip>Current hosts on /hostReads all status: live MDX entries, sorted by sessionDate.

The "add a new host" flow after Phase 2

1. Drop content/hosts/olivia-jones.mdx with frontmatter + intro letter. 2. Add their portrait to public/hosts/. 3. Set status: draft, share the preview URL with them. 4. When they say yes, flip to status: live. PR is ~5 lines + an image.

10 · Build order

Each week ends with a deployable, reviewable state. Don't carry half-finished routes across week boundaries — feature-flag if needed.

End of 4
Phase 2 close-out

Lighthouse + axe full sweep. Manual keyboard walkthrough on every new route. Tag v0.2.0. Update Task List.html with what's outstanding.
