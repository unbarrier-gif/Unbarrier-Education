01 · Naming convention

One pattern. Lowercase. Hyphens. Predictable.

{category}-{subject}-{variant}-{size?}.{ext}

category   logo · mark · illo · photo · badge · og · icon · email · print · bg
subject    the thing it is (kebab-case)
variant    treatment or version (closed set — see below)
size       optional pixel width when multiple sizes exist (180, 512, 1200)
ext        svg · png · jpg · webp · ico · pdf

Variant suffixes — closed set

Don't invent new variants. Extend this list with a doc edit (and bump §17 changelog).

  • Colour mode: colour · green · white · black · mono
  • Crop: circle · square · landscape · portrait
  • Composition: strap (with strapline) · nostrap · icon · full · lockup
  • Use-context: hero · thumb · avatar · banner · header · footer
  • Density / size: trailing pixel width (longest edge) — 180, 512, 1200, 2x

Rules — non-negotiable

  • All lowercase. Vercel/Linux are case-sensitive — Nici-Portrait.png ≠ nici-portrait.png in production.
  • Kebab-case only. No spaces, no underscores, no camelCase. Spaces become %20 in URLs and break copy-paste.
  • No version numbers in filenames (v2, final, final-final). Version is what git is for.
  • No dates in filenames unless the artefact itself is date-bound (print-flyer-cardiff-2026-04-29.pdf).
  • British English in subject words (colour, not color) — matches the rest of the codebase and the brand voice.
  • Extensions tell the truth. SVG for marks; PNG for transparent illustrations; JPG for photos; ICO for legacy favicons; PDF for print; WebP/AVIF only as <picture> alternates.
  • Filenames are forever. Once an image is in an email, on a flyer, or on a deployed page, the URL must keep working. Renaming requires a redirect.

    ├── illustrations/                # cosmic hand-drawn library (PNG)

    ├── badges/                       # Apple + accreditation
    ├── icons/                        # PWA / iOS / Android variants
    ├── email/                        # bitmap headers + footers for MailerLite
    └── bg/                           # decorative backgrounds (rare)

print-assets/                         # outside public/, never deployed
├── flyers/
├── business-cards/
├── banners/
└── slide-templates/
  • Why og/ is its own folder, not under assets/: OG cards are site-meta, not site-content. Lots of tooling crawls /og/ directly.
  • Why print-assets/ is outside public/: print artwork is heavy CMYK PDFs that should never be served as web traffic.
  • Don't nest deeper than 2 levels. If a folder grows past 30 files, prefix-group inside it (illo-trans-*, illo-hero-*) — don't create illustrations/transparent/.
  • Logos are SVG-first, illustrations are PNG. Marks are geometric and vector-clean; the cosmic illustrations have grain, gradients and shading that don't survive SVG export.
  • Photos are JPG (mostly). JPG is ~70% smaller than PNG for photographic content. Reserve PNG for circular crops where transparency is genuinely needed.

03 · Brand & meaning

What each image says, and where it speaks loudest.

This is the editorial layer — the "why" beneath every visual. The brand is built on a small library of recurring metaphors. Images aren't decoration; each one is a sentence in the brand's voice.

The signature moment — "bring the joy"

The triangular spotlight pouring colour out of dark. This is the brand's whole thesis in one image: the dark background is the system as it is — the colour, planets, and jumping figure are what becomes possible when barriers come down. Used once per surface, never twice. It's the punctuation, not the sentence.

Where: /hello hero (≥720px). Homepage hero. About page closer. Cardiff flyer back.

The character — the jumping figure

Round-faced, pink/orange hair, orange tee, blue jeans, jumping or floating. The character is "you" — the student, the educator, the person finally finding space. Use them when the moment is about release or self-recognition: success states, confirmations, end-of-flow.

Where: Loop Breakers landing hero. "Thanks for signing up" confirmations. Blog post end-cards.

Editorial rules

  • One illustration per section, max. The brand voice is "quiet authority" — visually overloading a section with planets + pyramids + basketball is the opposite.
  • Pair illustration with whitespace. Let the amethyst breathe.
  • Match colour to section accent. If a section is using Pearl Aqua (audit), choose an illustration whose dominant tone harmonises — ruler, helmet — not the orange planet.
  • Don't crop people. The character is whole. Cropping a face or limbs reads as detached; the brand is about belonging.
  • Never on white. All illustrations live on amethyst. They lose their meaning on light backgrounds.
  • Never AI-generated people, never stock photography. When a photo is needed, it's a real portrait on plain amethyst.

14 · Production rules

Sizes, formats, alt text, performance.

Always use Next.js <Image>

import Image from "next/image";
import nici from "@/public/assets/photos/photo-nici-portrait-circle.png";

<Image
  src={nici}
  alt="Nici Foote, smiling, wearing a green jumper, on amethyst background"
  width={56}
  height={56}
  priority={isAboveFold}
/>

Importing the asset (rather than a string path) lets Next.js auto-generate WebP/AVIF, lazy-load below-fold, and prevent layout shift.

Alt text — single source

Maintain alt text in a JSON sidecar per folder, not inline in components. Claude Code reads from this file:

// public/assets/illustrations/alt.json
{
  "illo-hero-bring-the-joy.png":
    "A triangular spotlight pouring colourful planets, beakers and a jumping figure out of a dark sky.",
  "illo-planets.png":
    "Four stylised planets in fuchsia, acid green, orange and sky blue.",
  ...
}

Decorative-only illustrations (background glows, dividers) get alt="" — explicitly empty, never omitted.

Performance budget

  • Hero PNG ≤ 180KB after Next.js compression.
  • Inline illustration ≤ 80KB.
  • Photo ≤ 120KB at q85.
  • Total page weight (images) ≤ 500KB on /hello, ≤ 800KB on home.
  • Lighthouse Performance ≥ 90 mobile is part of the spec.

Caching

Vercel auto-caches /public for 1 year. Don't fight it. Corollary: never overwrite an image at the same filename mid-deploy. Browsers will serve stale. If an asset changes meaningfully, change the filename or rely on Next.js's content-hash on imported assets.

15 · Decisions made (no approval needed)

Executive calls I'm taking as head designer.

These are operational decisions inside scope. I'll proceed unless you tell me otherwise.

15.1Naming convention is locked

{category}-{subject}-{variant}-{size?}.{ext}, all lowercase kebab-case, British spelling, closed variant set. Existing files in assets/ already mostly follow this; I'll rename the strays (notably nici-portrait*.png → photo-nici-portrait*.png, badge files prefixed badge-apple-).

15.2Folder structure: 6 sub-folders under public/assets/

logos · illustrations · photos · badges · icons · email + a sibling public/og/. Print stays outside public/ in print-assets/. No deeper nesting.

15.3OG cards generated by templated route, not hand-built PNGs

Phase 2 ships a Next.js app/og/[slug]/route.tsx using ImageResponse. One file, one set of components, every page's OG card auto-generated. Saves indefinite design debt — when the brand updates, every card updates. 2–3 hrs upfront.

15.4Favicons generated via realfavicongenerator.net

One pass through that tool with mark-icon-green.png + amethyst background #210a33 produces every size and the manifest. Verified against the table in §08–09; renamed if it deviates.

15.5Re-export oversized images at Phase 2 kickoff

Six files exceed budget: illo-planets (705KB), illo-full-illustration (459KB), illo-hero-bring-the-joy (461KB), illo-bring-the-joy-figure (441KB), illo-nonbinary-figure (441KB), photo-nicki (1.9MB), photo-gemma (1.2MB). I'll re-export at target sizes during the Phase 2 build.

15.6Alt text lives in JSON sidecars, not React components

One alt.json per folder. Single edit point; Claude Code, VAs, and future humans all touch the same file. Component code reads it.

15.7Email images are append-only
