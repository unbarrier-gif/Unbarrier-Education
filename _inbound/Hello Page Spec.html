01 · Scope & non-goals

What ships, what doesn't.

  • One API route: POST /api/say-hi (forwards to inbox + adds to MailerLite group)

Out of scope (Phase 2)

  • Homepage /, /loop-breakers, /blog — not this PR

  • Dynamic "next 3 sessions" from TidyCal API — Phase 2
  • Resource library, sketchnote gallery, Founding Member landing

02 · Stack & conventions

Next.js 14 · App Router · TypeScript.

FrameworkNext.js 14, App Router, TypeScript strict mode
StylingCSS Modules + global tokens. Copy colors_and_type.css from this project to app/globals.css verbatim. Use the CSS custom properties — don't re-invent.
FontsOutfit + Comfortaa via next/font/google. Variable fonts. font-display: swap.
FormsReact Server Components for the page; client component only for the form. Native <form action={serverAction}> — no React Hook Form.
ValidationZod for the say-hi payload.
Email forwardResend (resend.com) — add RESEND_API_KEY to env. Free tier covers our volume.
AnalyticsPlausible script, data-domain="unbarrier.me". Custom events via window.plausible(name).
DeploymentVercel auto-deploys on push to main. PRs get preview URLs.
LintingESLint + Prettier (Next.js defaults). Husky pre-commit optional.

06 · Behaviour & events

Plausible events & form flows.

Plausible custom events

TriggerEvent nameProps
CTA card click (any of 4)cta_click{ card: "tuesday" | "guest" | "coaching" | "schools" }
Newsletter form submit (success)newsletter_signup—
Say-hi form submit (success)say_hi_sent—

Use Plausible's recommended snippet with script.outbound-links.tagged-events.js. CTA cards have target="_blank" rel="noopener" and use Plausible outbound auto-tracking and the manual cta_click event for redundancy.

Newsletter form (POST direct to MailerLite)

POST https://connect.mailerlite.com/api/subscribers
Authorization: Bearer ${MAILERLITE_API_KEY}
Content-Type: application/json
Accept: application/json

{
  "email": "...",
  "groups": ["${MAILERLITE_GROUP_ID}"],   // 185831469000688733
  "status": "active"
}

→ on 2xx: show "Welcome. Check your inbox." + fire newsletter_signup
→ on 422 (already subscribed): show same success message (don't leak state)
→ on 4xx/5xx: show error copy

Say-hi form (POST to /api/say-hi)

Body schema (Zod):
  {
    email:    z.string().email(),
    message:  z.string().min(1).max(2000),
    honeypot: z.string().max(0)   // hidden field, must be empty
  }

Server action:
  1. Validate with Zod → 400 on fail
  2. Drop if honeypot non-empty → 200 fake-success (don't tip off bots)
  3. Add subscriber to MailerLite group (same call as above; ignore 422)
  4. Send email via Resend:
       to:      process.env.SAY_HI_FORWARD_TO   // hello@unbarrier.me
       from:    "say-hi@unbarrier.me"
       subject: `[say hi] ${email}`
       text:    `From: ${email}\n\n${message}`
  5. Return { ok: true } → client shows confirm copy + fires say_hi_sent

Rate limiting

Add a simple in-memory rate limit on /api/say-hi — max 5 requests per IP per hour. Use a Map; clear on server restart is fine for Phase 1. Vercel Edge Config or Upstash if it ever gets abused — Phase 2.

08 · Accessibility (non-negotiable)

This is Unbarrier. The page must clear WCAG 2.1 AA.

  • Semantic HTML — <main>, <section>, <h1> exactly once, headings in order, landmarks named
  • Contrast — every text-on-background combo ≥ 4.5:1. The palette in colors_and_type.css is built for this; don't change opacities below --text-muted for body copy
  • Focus rings — keep :focus-visible from globals.css; never set outline: none
  • Forms — every <input> has a real <label> (visible or sr-only). Errors announced via aria-live="polite"
  • Touch targets — minimum 44×44px for every CTA card and button (mobile-first; Cardiff visitors will be on phones)
  • Motion — respect prefers-reduced-motion on any transitions
  • Lighthouse — must score ≥ 95 Accessibility before merge

11 · Step 2 · Design pass & live links

What's wrong on feat/hello right now — and the fix.

The page renders, but it doesn't read as Unbarrier yet. Three problems from the live preview: (1) the hero needs to be quieter and more confident — type-only, no illustration, just the wordmark + headline + bio, (2) every section is a grey rounded rectangle on amethyst — there's no visual rhythm, no accent system per card, (3) the CTA cards link to # placeholders. Step 2 fixes all three. No new sections, no new copy — same structure, properly designed and wired.

Status of links right now (live preview)

All four CTA cards have href="#". Newsletter button posts but doesn't route. Footer privacy / terms 404. None of these can ship to Cardiff like this — the QR scan would land on a page where nothing works.

Hero direction — locked decision

The /hello hero is type-only. No triangular spotlight illustration. No "bring the joy" Cherry Bomb moment. No magenta circle. No portrait. Just: small green logo dot + unbarrier.me wordmark · headline · one-paragraph bio. This is a handheld page reached by QR — quiet and confident beats decorative. The bring-the-joy moment lives on the homepage, not here.

11.1 — Hero: type-only, confident, no illustration

  • Wordmark row at the top: a 22×22px border-radius: 6px Spring Green square (#38ff99) followed by the lowercase wordmark unbarrier.me in Comfortaa 700, ~1.4rem, white. 12px gap between dot and wordmark. Sits 0 above the headline.
  • Headline: designed for difference. — Outfit 800, font-size: clamp(2.4rem, 8vw, 3.6rem), line-height: 1.05, letter-spacing: -0.025em. White by default; wrap difference. in an <em> set to font-style: normal; color: var(--spring-green). The full stop stays inside the green span.
  • Bio paragraph: Comfortaa 400, ~1rem, line-height: 1.7, color: var(--text-muted). The words Loop Breakers are bolded and white (color: var(--text); font-weight: 700) — only those two words. max-width: 42ch so the line breaks feel deliberate on mobile.
  • No illustration on this route. Do not import any PNG hero asset for /hello. Do not render glow orbs in the hero — the page is calm by design.
  • Spacing: wordmark → headline 28px · headline → bio 20px · bio → "NEXT SESSIONS" eyebrow 44px.
  • No eyebrow above the headline. Earlier drafts had INCLUSION · DIGITAL ACCESS · STUDENT VOICE — drop it. Wordmark is enough.

  • Input: dark amethyst (rgba(0,0,0,0.3)), 1.5px rgba(255,255,255,0.12) border, 12px radius, 14px vertical padding. Focus ring: 0 0 0 3px rgba(255,194,3,0.25).

11.4 — Say-hi band: orchid accent, calmer treatment

  • Container: background: rgba(219,125,204,0.06) · border: 1px solid rgba(219,125,204,0.25) · border-radius: 18px · padding: 28px. Softer than the yellow newsletter band — this is the "no agenda" moment, deliberately quiet.
  • Heading "Just say hi." — Outfit 800, same scale as newsletter heading, white. Sub copy var(--text-muted).
  • Email + textarea: stack vertically. Same input chrome as newsletter, focus ring uses orchid: 0 0 0 3px rgba(219,125,204,0.25).
  • Send button: Spring Green background (matches the existing live preview's button — keep it), amethyst text, pill, right-aligned. min-width: 120px.
  • Honeypot: hidden <input name="website"> with tabindex="-1", aria-hidden="true", position: absolute; left: -9999px. Already in spec §06 — confirm it's actually rendered.

11.5 — Section rhythm + glow orbs

  • Vertical rhythm: clamp(3rem, 6vw, 5rem) between bands. Currently they're touching.
  • Section bar: 2px linear-gradient accent→transparent at the top of each band — 80px wide, left-aligned. Colour matches the band's accent. (Yellow for newsletter, orchid for say-hi.)
  • Background glows: two more <Glow>s lower on the page — yellow orb behind newsletter, orchid orb behind say-hi. filter: blur(160px); opacity: 0.08.
  • Max-width: the page max-width should be 720px on this route (it's a reading/handheld page, not a landing). Anything wider feels too corporate for the "say hi" tone.

11.6 — Footer: real links, real co. number

  • Co. number is known — 16603630. Replace the live "(Co. No. 16603630)" line; current copy is right but the wrapping looks broken on the screenshot. Use a non-breaking space inside "Co. No. 16603630".
  • Privacy / Terms must resolve. Phase 1 should already have shipped /legal/privacy and /legal/terms from Legal Pages v1.html. If not — add them in this same Step 2 PR. They are not optional for a public page that captures email.
  • Hover state: footer links fade from var(--text-muted) → var(--spring-green) on hover, 150ms.

11.7 — Wire the analytics events that the spec already required

§06 calls for cta_click, newsletter_signup, say_hi_sent. Confirm in the Step 2 PR that all three fire in the Plausible dashboard from a real device (not just curl). Until that's verified, this step isn't done.
