02 · API call

POST to MailerLite — public form endpoint, no key needed

Endpoint

POST https://assets.mailerlite.com/jsonp/{ACCOUNT_ID}/forms/{FORM_ID}/subscribe

Where {FORM_ID} = 185568935471482009. Account ID is exposed in MailerLite's embed snippet — Nici will paste it in chat (Forms → "Embedded form" → "Get embed code" → copy the number after /jsonp/).

Request body (URL-encoded form data)

fields[email]=user@example.com
fields[source]=homepage   // or "blog" or "loop-breakers"
ml-submit=1
anticsrf=true

Better path — server-side via API token

If we want clean tagging and richer error handling, route through a Next.js API route (/api/subscribe) using MailerLite's REST API:

POST https://connect.mailerlite.com/api/subscribers
Authorization: Bearer $MAILERLITE_API_TOKEN
Content-Type: application/json

{
  "email": "user@example.com",
  "groups": ["{NEWSLETTER_GROUP_ID}"],
  "fields": { "source": "homepage" }
}

Recommendation: use the server-side route. Keeps the API token in Vercel env vars (not the browser bundle), gives proper error responses, lets us log to Plausible.

03 · UX behaviour

What the form does

  • Inline success state — no redirect. Replace form with: "You're in. Check your inbox — first note arriving now."
  • Inline error state — same area. "Something went wrong. Try again, or email nici@unbarrier.me."
  • Email validation — HTML5 type="email" + browser-native error message; no custom JS validator
  • Loading state — button text: "Subscribing…" while in flight; disabled state
  • Keyboard — Enter submits; visible focus ring on input + button (spring-green, 2px offset)
  • Reduced motion — no slide/fade transitions on success state if prefers-reduced-motion: reduce
  • Screen reader — success message in aria-live="polite" region
